# Implementation Rules

1. Preserve the editorial Bauhaus design system: strong scale contrast, hairline rules, red accents only where intentional, and numbered content.
2. Use Eleventy and content files for public content; do not introduce a frontend framework without a concrete need.
3. Never invent credentials, personal biography, project outcomes, metrics, clients, or achievements. Use explicit placeholders instead.
4. Keep public JavaScript minimal and respect `prefers-reduced-motion`.
5. Build and inspect the static output after each meaningful phase.
6. Do not implement admin authentication or GitHub publishing until the public design and content foundation has been approved.
