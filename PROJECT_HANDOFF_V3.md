## 0. Executive Architecture Summary

The system is a high-performance, editorial portfolio and personal publishing platform powered by **Eleventy**, **Node.js**, **Markdown/YAML**, and an **Obsidian-inspired personal admin workspace**.

```text
                           GITHUB REPOSITORY
                       (Canonical Source of Truth)
                       Markdown + YAML + WebP Assets
                                     |
               +---------------------+---------------------+
               |                                           |
               v                                           v
      VERCEL ADMIN SERVER                       GITHUB ACTIONS WORKFLOW
      (Private Admin App/API)                   (Static Eleventy Builder)
      • Passcode & Github OAuth Auth            • Auto-triggers on git push
      • Quill.js WYSIWYG & Source Editor        • Runs validation checks
      • Note Promotion & Media Manager          • Generates static HTML/CSS/JSON
      • GitHub API Direct Commits                          |
               |                                           v
               +---------------------------------> GITHUB PAGES SITE
                                                  (Public Portfolio)
```

### Key Architectural Principles
- **No Database Dependency**: GitHub is the single, version-controlled source of truth. Content is stored as clean Markdown (`.md`) with YAML frontmatter.
- **Dual Surface Architecture**: Public site is statically compiled and hosted on **GitHub Pages**; private admin interface runs on **Vercel** (or local Node.js server).
- **Stealth Access**: Admin entry point is completely hidden from public visitors and unlocked via secret `$passcode` inside the search bar.
- **Editorial Bauhaus Design**: Strict adherence to off-white paper (`#f2f0ea`), deep ink (`#111`), hairline rules (`#d4d1c9`), red accent (`#e03c31`), DM Mono, Inter, and numbered navigation.

## 3. Stealth Admin Access & Authentication Flow

### Unlocking the Admin Console
1. Hover or click the **magnifying glass search icon** in the top navigation header on any public page.
2. Type `$abantika2026` into the search bar.
   - As soon as the first character (`$`) is typed, the search input automatically masks into a password field, and the status pill changes to `COMMAND`.
3. Press **Enter**.
   - The backend validates the passcode via `POST /api/auth/passcode`.
   - On success, the badge displays `UNLOCKED →` with a red highlight, setting an HTTP session cookie and redirecting to `/admin/`.
   - On failure, the badge displays `DENIED`.

## 4. Production Deployment & Operations Guide

### Option A: Running & Editing Locally
1. Start the local development server:
   ```bash
   node server/admin-api.js
   ```
2. Open your browser:
   - **Public Site**: `http://localhost:8080/`
   - **Admin Console**: `http://localhost:8080/admin/`

### Option B: Deploying Public Site to GitHub Pages
1. Ensure the repository has GitHub Pages enabled:
   - In GitHub: **Settings** → **Pages** → **Build and deployment** → **Source**: Select `GitHub Actions`.
2. Push changes to the `main` branch:
   ```bash
   git add .
   git commit -m "Deploy latest updates"
   git push origin main
   ```
3. GitHub Actions will automatically execute `.github/workflows/deploy.yml`, build the site using Eleventy, and publish to:
   `https://abantika06.github.io/abantika.github.io/`

### Option C: Deploying Remote Admin to Vercel
1. Import the repository into **Vercel**.
2. Set Environment Variables in Vercel Dashboard (**Settings** → **Environment Variables**):
   - `ADMIN_PASSCODE`: `abantika2026`
   - `GITHUB_TOKEN`: `ghp_xxxxxxxxxxxxxxxxxxxx`
   - `GITHUB_REPO_OWNER`: `ABANTIKA06`
   - `GITHUB_REPO_NAME`: `abantika.github.io`
3. Deploy! Vercel will host the serverless API routes while GitHub Pages serves the public site.
